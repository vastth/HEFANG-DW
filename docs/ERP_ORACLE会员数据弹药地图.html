推荐的一期分析链路

先把能闭环的链路跑起来，再做跨平台统一会员
会员主键

C_CLIENT_VIP.ID

作为 ERP 会员维表主键，补等级、生日、开卡门店、积分、OpenID 等画像字段。

交易桥

M_RETAIL.C_VIP_ID

作为会员销售主桥；2026 年以来覆盖 46,656 单，会员键可 100% 回连。

商品明细

M_RETAILITEM

通过 M_RETAIL_ID 回到单头，再补商品 / SKU 偏好；不要用明细 C_VIP_ID 做主桥。

门店 / 导购

C_STORE / HR_EMPLOYEE

门店归因走单头 C_STORE_ID；销售员归因走 SALESREP_ID，需过滤异常值 0。

会员运营

FA_VIPACC / FA_VIPINTEGRAL_FTP

叠加积分、累计消费、最近消费与价值分层，形成可经营的人群标签。

会员等级结构

先看 ERP 会员体系的可解释标签
等级会员数占比判断
珍珠会员658,651最大会员池，适合做基础活跃 / 召回。
黄金会员333,960第二大会员池，适合做升级转化。

等级分析可以马上做什么

  • 按等级看销售贡献、客单价、复购率、最近消费时间。
  • 珍珠 → 黄金、黄金 → 白金的升级漏斗。
  • 高等级会员的门店集中度与商品偏好。
  • 结合 FA_VIPACC 做“等级高但近期沉睡”名单。

销售单头 SALESREP_ID 2026 覆盖 22.89%，且大部分能回连员工主档，可做销售员会员销售贡献。

需谨慎

商品偏好

可以通过单头会员回连明细商品做偏好，但不能直接用明细 C_VIP_ID，因为覆盖只有 0.19%。

二期专题

全域会员融合

Oracle 内有 SY / YZ 平台会员域，但需单独确认 SY_ID、手机号、OpenID、平台账号的桥接优先级。

限制与注意事项

这些点会直接影响建模方案

不要直接踩的坑

  • 不要用手机号做唯一会员主键。ERP 会员主档手机号覆盖只有 10.06%，且属于敏感字段。
  • 不要用明细表 C_VIP_ID 做会员销售主链。2026 年明细覆盖只有 0.19%，主链必须走单头 M_RETAIL.C_VIP_ID。
  • 不要把 SY 域直接混入 ERP 会员主口径。SY 表量级很大，语义更像平台同步域，应单独做桥接专题。
  • 不要默认导购字段全可用。ERP 销售员链路可用，但平台 / 有赞导购需要继续验证字段语义。

一期建议落地口径

  • 会员维表：优先 C_CLIENT_VIP + C_VIPTYPE + FA_VIPACC。
  • 会员销售事实：优先 M_RETAIL 单头会员键 + M_RETAILITEM 商品明细。
  • 员工归因：M_RETAIL.SALESREP_ID → HR_EMPLOYEE.ID，过滤 0 或异常员工键。
  • 全域会员：作为二期，用 SY_MEMBER / SY_VIP_BIND 单独做桥接矩阵。
