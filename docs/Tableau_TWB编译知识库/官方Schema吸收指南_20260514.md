# Tableau 官方 Schema 吸收指南

> 版本：v0.1  
> 日期：2026-05-14  
> 适用范围：HEFANG-DW 中通过 Copilot / Agent 创建、修改、修复 Tableau `.twb` / `.twbx` 时的官方 XSD 使用边界。

## 1. 结论

- `tableau/tableau-document-schemas` 是 Tableau 从 2026.1 起公开的官方 TWB XSD 基线，可作为 `.twb` XML 结构校验的最高优先级参考。
- 官方 XSD 只解决结构 / 语法层问题，不能替代字段语义校验、连接可用性校验、计算字段引用校验和 Tableau 重开渲染验证。
- 当前 HEFANG 存量工作簿大量为 `<workbook version="18.1" source-build="2025.3.1 ...">`，不在官方公开的 2026.1 XSD 直接覆盖范围内；不得为了通过 XSD 校验而擅自把存量工作簿根节点升级为 `26.1`。
- 本仓库已在 `tableau_worksheet_mcp` 中新增 `validate_workbook_schema` 能力：支持自动识别版本、按需缓存官方 XSD、为官方主 XSD 补本地 `user` 命名空间兼容 schema，并对不受支持的旧版本返回 `skipped`。

## 2. 官方仓库事实

| 事实 | 说明 |
|---|---|
| 仓库 | `https://github.com/tableau/tableau-document-schemas` |
| 目录约定 | `schemas/YYYY_R/twb_YYYY.R.0.xsd` |
| 当前已验证版本 | `schemas/2026_1/twb_2026.1.0.xsd` |
| TWB 版本映射 | `<workbook version="26.1">` 对应 `twb_2026.1.0.xsd` |
| Manifest 简化 | 直接创作新 TWB 时，可在 `<document-format-change-manifest>` 内使用 `<ManifestByVersion />` 代替手工 feature 清单 |
| TWBX 边界 | 官方 schema 不校验 `.twbx` 包；只能校验包内提取出的主 `.twb` XML |
| 支持边界 | XSD 结构校验通过，不代表 Tableau 一定能打开或正确渲染 |

补充实测：官方 `twb_2026.1.0.xsd` 只包含主 XSD，`xs:import namespace="http://www.tableausoftware.com/xml/user"` 没有随仓库附带 `schemaLocation` 文件；本地 MCP 通过生成最小 `UserAttributes-AG` companion schema 解决 `user:UserAttributes-AG` 加载问题。

## 3. Agent 使用流程

### 3.1 新建或大改 `.twb`

1. 先读取目标 Tableau / Desktop 版本与目标 workbook 根节点 `version`。
2. 若目标是新建且明确面向 Tableau 2026.1+，优先使用官方 schema 对齐：
   - 根节点 `version` / `original-version` 与 XSD 版本对应。
   - 使用 `<ManifestByVersion />` 简化 manifest。
   - 关键结构优先按官方 XSD 的元素顺序、必填属性、枚举值编写。
3. 若目标是修补存量 HEFANG 工作簿，优先保持原根节点版本和 Tableau 保存风格，不为 XSD 校验而升版本。

### 3.2 修改存量 `.twb`

1. 修改前备份目标文件。
2. 先做 XML parse，确认不是基础 XML 损坏。
3. 调用 `tableau_worksheet_mcp` 的 `validate_workbook_schema`：
   - `status="passed"`：官方结构校验通过，但仍需后续语义 / 渲染验证。
   - `status="failed"`：优先查看 `errors[*].path` 和 `reason`，修复结构、顺序、必填属性或枚举值。
   - `status="skipped"`：通常表示旧版本不在官方公开 XSD 覆盖范围内，继续走样板经验、字段画像和 Tableau 重开验证。
4. 对 worksheet 字段绑定继续使用 `validate_field_refs`，不要把 XSD 通过当成字段真实存在的证据。
5. 用户关闭并重开 Tableau 后，如果出现报错 / 空白 / 字段失效，继续按错误修复台帐流程处理。

## 4. 校验分层

| 层级 | 工具 / 方法 | 解决的问题 | 不能解决的问题 |
|---|---|---|---|
| XML 语法 | `ElementTree.parse()` | 文件是否为合法 XML | Tableau 结构顺序、字段语义 |
| 官方 XSD | `validate_workbook_schema` | 2026.1+ TWB 的结构、必填属性、枚举值 | 连接可用、计算字段函数、命名引用、旧版本工作簿 |
| 工作簿画像 | `open_workbook_profile` / `get_worksheet_profile` | datasource、worksheet、dashboard、依赖字段范围 | 复杂 UI 渲染效果 |
| 字段校验 | `validate_field_refs` | 指定 worksheet + datasource 作用域内字段是否存在 | 公式执行结果、数据库数据正确性 |
| Tableau 重开 | 用户打开工作簿 | 真实语义加载和渲染 | 自动化复现难、需用户反馈截图或报错 |

## 5. 对 HEFANG 当前存量工作簿的特别规则

- 当前抽样工作簿均显示 `version="18.1"`，虽然 `source-build` 来自 Tableau 2025.3.1；这类文件默认按旧版存量 workbook 处理。
- `validate_workbook_schema` 返回 `skipped` 时不是失败，而是官方 schema 覆盖边界提示。
- 存量修补仍以“最小 XML patch + 字段画像 + Tableau 重开验证”为主。
- 只有用户明确要求新建面向 Tableau 2026.1+ 的工作簿，才把官方 XSD 作为必跑校验。
