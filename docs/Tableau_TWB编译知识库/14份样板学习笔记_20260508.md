## 3. Dashboard 编译经验

### 3.1 尺寸策略

29 个 dashboard 全部使用固定尺寸 `sizing-mode="fixed"`，常见尺寸包括：

| 尺寸 | 出现次数 | 适用判断 |
|---|---:|---|
| 1500 × 900 | 3 | 宽屏首页 / 销售总览常用 |
| 1731 × 1200 | 3 | 明细与探索页常用，纵向空间更充足 |
| 1200 × 800 | 3 | 中等复杂度总览页 |
| 1400 × 1000 | 3 | 平衡型经营看板 |
| 1200 × 1000 | 2 | 侧重纵向卡片 / 表格 |
| 1900 × 1050 | 2 | 大屏或广告投放分析页 |
| 1540 × 1000 | 2 | 营销 / 邮件分析类总览页 |
| 1300 × 1200 | 2 | 活动分解 / 下钻页 |
| 1463 × 1227 | 2 | 高度较大的管理驾驶舱 |
| 1600 × 900 | 2 | 宽屏总览页 |

编译结论：HEFANG 首版 dashboard 建议继续固定尺寸，而不是自动尺寸。销售首页优先选 1400 × 1000 或 1500 × 900；如果门店明细区较高，可选 1600 × 1000。

### 3.1.1 多页工作簿结构

- 14 份样板中，多数高完成度案例不是只做单页总览，而是拆成 Overview、Detail、Records / Explore 多页结构。
- `E-Commerce (Software) Sales Dashboard #VOTD`、`Email Marketing Campaign Dashboard`、`Merchandise Sales Dashboard`、`Sales Analysis Dashboard #VOTD`、`Sales Dashboard _ #VOTD` 都体现了“总览负责阅读、下钻负责分析、记录页负责明细/导出”的分工。

编译结论：HEFANG 后续新建 Tableau 工作簿时，优先规划成三段式结构：

1. Overview：KPI、趋势、排名、地图等高层阅读页面。
2. Detail：按渠道、品类、门店、活动等主题下钻。
3. Records：明细表、导出、核对。

### 3.2 Zone 与坐标

- dashboard 根 zone 通常使用 `x="0" y="0" w="100000" h="100000"`，内部区域按 0 到 100000 的比例坐标切分。
- 老样板使用 `type` 表示 `layout-basic`、`layout-flow`、`text`、`bitmap`、`paramctrl`；新样板大量使用 `type-v2`。编译器必须先检测目标 `.twb` 已有写法，再沿用同一种属性。
- worksheet zone 经常没有 `type` / `type-v2`，只通过 `name="工作表名"` 挂载工作表；不能因为 `type` 为空就删除。
- `layout-flow` 的 `param="horz"` / `param="vert"` 是行列容器的核心标识；`layout-basic` 更像绝对定位画布。
- 常见辅助节点包括 `empty` 留白、`text` 标题 / 标签、`bitmap` 背景或图标、`paramctrl` 参数控件、`filter` 筛选器、`dashboard-object` 导航 / 按钮类对象。

编译结论：自动生成 dashboard 时，先建立固定尺寸根布局，再用 `layout-flow` 做粗网格，最后把 worksheet zone、文本、筛选器挂进去；不要一开始堆大量浮动对象。

### 3.3 背景图与装饰

部分样板使用 `bitmap` 当背景或图标，例如电商 dashboard 把整张背景图作为底图。该模式视觉冲击强，但后续维护成本高。

HEFANG 编译建议：

1. 首版优先使用 Tableau 原生容器、边框、浅背景色。
2. 只有在结构稳定后，再考虑把品牌图、图标、装饰线落成 `bitmap`。
3. 如果使用 `bitmap`，必须同步检查 `.twbx` 打包资源路径，单独 `.twb` 不一定能带走图片。

| 高频 mark class | 出现次数 | 适用场景 | 编译建议 |
|---|---:|---|---|
| Automatic | 211 | Tableau 默认图、KPI 文字、基础汇总 | 适合首版快速落地 |
| Shape | 159 | 图标、状态点、装饰按钮 | 需要 shape 资源时再用，避免首版资源缺失 |
| Bar | 136 | 排名、对比、构成 | 销售 / 门店对比优先使用 |
| GanttBar | 79 | 进度条、时间轴、卡片条形背景 | 可用于达成率 / 进度条式 KPI |
| Line | 52 | 趋势、累计走势 | 销售趋势与累计进度优先使用 |
| Circle | 37 | 散点、状态点 | 可用于气泡 / 分布图 |
| Area | 27 | 累计面积、占比趋势 | 适合月内累计趋势背景 |
| Pie | 22 | 构成占比 | 首版慎用，优先条形图表达结构 |
| Text | 19 | KPI 文本卡、明细标签 | 顶部 KPI 卡最稳定 |
| Square | 15 | 热力图、矩阵 | 可用于门店 / 日期矩阵 |

编译结论：HEFANG 首页首版优先使用 Text、Bar、Line、GanttBar 四类，Shape / bitmap / Pie 放到增强阶段。

### 4.1 KPI 卡类型

结合样板 `.twb` 结构和 10 张同名 PNG，可把高频 KPI 卡拆成三种稳定实现：

1. 纯数值卡：标题 + 主数值，适合单指标摘要。
2. 数值 + 对比卡：标题 + 主数值 + 同比/环比 + 上期/去年同期说明。
3. 数值 + 对比 + sparkline 卡：在第二类基础上再挂一个迷你趋势 worksheet。

编译结论：稳定做法不是把所有元素堆进一个 worksheet，而是“文本 worksheet 承担标题/主数值/对比文字，趋势 worksheet 单独承载 sparkline / mini bar”。

### 4.2 轻量漏斗优先级

- `Marketing Funnel` 与 `Email Marketing Campaign Dashboard` 提供了强视觉的漏斗 / Sankey 样板，但都依赖更复杂的 mark 和交互。
- 对 HEFANG 首版，优先采用单 worksheet 的 Bar / GanttBar 条形漏斗来表达阶段人数、金额或转化率；polygon / path 仅在结构稳定后再加。

## 5. 参数、计算字段与交互经验

### 5.1 参数值格式

样板中的参数常见格式：

| 类型 | 示例格式 | 编译注意 |
|---|---|---|
| string | `"Revenue"`、`"CM vs CM PY"` | 字符串值需要带双引号 |
| integer | `2024`、`53`、`1` | 指标选择器常用整数枚举 |
| real | `2025.`、`0.56928464232116049` | Tableau XML 中实数可能保留尾部小数点 |
| date | `#2020-01-01#` | 日期参数使用井号包裹 |
| boolean | `true`、`false` | show/hide、toggle 常用 |

### 5.2 计算字段模式

样板高频计算模式包括：

1. 指标选择器：`CASE [Parameters].[Metric] WHEN 1 THEN ... END`。
2. 周期选择器：按 Year / Month / Period 参数切换当前期、去年同期、上期。
3. CY / PY 分离字段：`IF YEAR([Order Date]) = [Parameters].[Current Year] THEN [Sales] END`。
4. LOD 固定最大值：`{ FIXED : MAX(...) }` 用于统一 KPI 标尺、Top 卡片比例。
5. 聚合后比例：先 `SUM()` 金额，再做除法，避免平均比例偏差。
6. 状态符号：用 `▲`、`▼`、`●` 或文本拼接生成轻量状态标签。
7. 日期范围标题：用 `DATENAME()`、`YEAR()`、`MIN()`、`MAX()` 拼接页头说明。

HEFANG 编译结论：销售看板 KPI、渠道贡献和趋势模块应优先采用“参数 / 计算字段驱动”的模式，但业务口径必须来自数据契约；Tableau 只做聚合、格式化、状态标签和展示切换。

### 5.3 交互动作

高频 action 节点：

| action 节点 | 出现次数 | 说明 |
|---|---:|---|
| `edit-parameter-action` | 75 | 参数动作，常用于点击切换指标、维度、时间粒度 |
| `action` | 64 | 通用 action，包含筛选 / 选择等 |
| `toggle-action` | 29 | 显隐容器或切换状态 |
| `export-button-action` | 28 | 导出按钮 |
| `ParameterAction` | 11 | 参数动作的窗口 / UI 配置痕迹 |
| `ParameterActionClearSelection` | 11 | 参数动作清除选中配置 |

编译结论：首版自动生成 dashboard 时，不应过早生成复杂 action。建议顺序是：先 worksheet 与 dashboard 可打开，再加筛选器作用范围，最后再加参数动作和 toggle。

### 5.4 Tab / Pill 控件实现顺序

- 多个样板的顶部导航看起来像 tab，但实现复杂度不同：有的只是文本高亮导航，有的已经接入参数动作。
- 稳定顺序应是：先做静态高亮的“假 tab”，确认布局、文案和页签命名稳定后，再升级到 `paramctrl` 或 `edit-parameter-action` 驱动的“真 tab”。

编译结论：HEFANG 首版默认优先“假 tab”，尤其在用户还未打开 Tableau 做渲染验证前，不要一次性上复杂参数动作。

## 6. 数据源与连接经验

样板覆盖的连接类型包括 `federated`、`hyper`、`excel-direct`、`textscan`、`google-sheets`、`dataengine`、`ogrdirect`。HEFANG 当前开发更关注 MySQL 实时连接，因此：

- 不从样板复制连接串、凭据、文件路径。
- 对用户已建好的数据源，只修改字段 caption、默认格式、隐藏字段、计算字段、worksheet / dashboard 引用。
- 如果必须新增数据源，应先让用户在 Tableau 中建好连接，再由 AI 补语义层和页面结构。
- 编译 `.twb` 时不要把 `.twbx` 包内图片、Hyper 或 Excel 路径写成项目事实。

## 7. HEFANG 首版编译路线

1. 基于用户当前 `.twb` 做备份。
2. 解析目标 `.twb` 的 `workbook` 版本、`source-build`、datasource 名称、`type` / `type-v2` 风格。
3. 保留现有 datasource 连接，只补字段别名、格式、计算字段。
4. 每个模块先生成独立 worksheet：KPI 用 Text，趋势用 Line，排名 / 构成用 Bar，进度用 GanttBar。
5. dashboard 采用固定尺寸 + 容器网格；首版不堆浮动图标、不复制复杂背景图。
6. 每次只新增一个模块或一组同质工作表，完成 XML 解析和 Tableau 打开验证后再继续。
7. 若 Tableau 打不开，优先回退最近一次备份，并对比新增节点，而不是继续叠加修改。
8. dashboard 首版可优先带 5 类筛选器骨架：日期范围、组织层级、渠道、品类、状态 / 标签；最终保留哪些筛选器再按主题删减。

## 8. 编译验收清单

| 检查项 | 要求 |
|---|---|
| XML 语法 | `ElementTree.parse()` 可正常解析 |
| workbook 元信息 | 不随意修改 `source-build`、连接信息、凭据 |
| datasource | 不丢失原有 datasource；新增计算字段必须引用真实字段 |
| worksheet | 新增 worksheet 必须有对应 window；名称唯一 |
| dashboard | 新增 dashboard 必须有 root zone、固定 size、对应 window |
| zone | `id` 不冲突；`type` / `type-v2` 与原工作簿风格一致 |
| 筛选器 | 统一 `report_date`、`data_version`，不混批次 |
| KPI 比例 | 必须汇总后计算，不能平均行级比例 |
| 空数据 | 首版 dashboard 遇到空数据时仍应显示标题、筛选器和“暂无数据”兜底文本 |
| Tableau 实测 | 用户打开后可识别页签、工作表、dashboard，并能正常渲染 |

## 9. 二轮视觉联合学习补充

首轮 XML 学习解决“`.twb` 能不能编译出正确结构”的问题；用户补充同名 PNG 后，二轮学习进一步解决“编译出的 dashboard 应该像什么”的问题。视觉层结论统一沉淀在 [视觉效果图联合学习_20260508.md](视觉效果图联合学习_20260508.md)，后续编译时优先按以下顺序使用：

1. 先选视觉母版：左侧导航、顶部 hero、卡片网格、漏斗专题、经营驾驶舱。
2. 再选固定尺寸：1200 × 800、1300 × 900、1500 × 900、1600 × 1000 或 1731 × 1200。
3. 最后落 XML：先 `layout-flow` 粗网格，再 worksheet / text / filter / paramctrl，复杂 bitmap 与 action 后置。
