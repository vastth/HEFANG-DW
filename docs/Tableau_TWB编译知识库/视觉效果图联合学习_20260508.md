## 3. 视觉母版与 XML 编译启示

### 3.1 左侧导航 / 品牌侧栏

代表样板：Advanced Superstore、Digital Ads、E-Commerce、Golf、Sales Analysis、Merchandise。

视觉特征：左侧占 12% 到 28% 宽度，放 logo、导航按钮、筛选器、说明文字或导出按钮；主内容区保持白底 / 浅灰底。

XML 启示：

- 用根 `layout-flow` 横向切分 sidebar 与 content。
- sidebar 内再用纵向 `layout-flow` 安放 `text`、`bitmap`、`paramctrl`、筛选器和导航对象。
- sidebar 的稳定顺序通常是“品牌区 → 导航区 → 筛选区 → 导出区 → 署名 / 链接区”；首版至少保证前三段结构清晰。
- HEFANG 首版建议先用文本按钮和背景色近似，图标、圆角和阴影在 Tableau 打开验证后再补。

### 3.2 顶部 hero / tabs / pill 控件

代表样板：Digital Ads、Marketing Campaign、Email Marketing、Sales Dashboard #VizOfTheDay、Golf。

视觉特征：顶部区域承担标题、用户信息、时间筛选、页面 tab、指标切换。pill 控件通常为圆角浅灰或深色描边，当前选中态使用品牌主色。

XML 启示：

- 顶部先用横向 `layout-flow` 固定高度，再嵌入 `text`、`paramctrl`、`dashboard-object`。
- 真实交互优先使用参数控件或 action；首版可先做静态 pill 文本，确认渲染后再加 `edit-parameter-action`。
- 不要一开始复制复杂 toggle，避免 Tableau 能解析但交互异常。
- 对 HEFANG 首版，优先先做“假 tab / 假 pill”的阅读层级，再决定是否升级为参数切换；避免把交互复杂度和布局复杂度同时拉高。

### 3.3 KPI 卡 + 微型趋势

代表样板：Digital Ads、E-Commerce、Email Marketing、Golf、Sales Analysis、Merchandise。

视觉特征：一个 KPI 卡通常包含标题、主数值、同比 / 环比变化、单位说明、迷你柱线图或 sparkline。

XML 启示：

- 稳定做法是“一个 KPI 文本 worksheet + 一个趋势 worksheet”组合成卡片，而不是把所有文字和图形硬塞进一个 worksheet。
- 微型趋势可用 `Bar`、`Line`、`Area` 或 `GanttBar`；达成率 / 进度条优先 `GanttBar`。
- KPI 比例仍必须按 HEFANG 规则聚合后计算，不允许对行级比例字段做平均。
- 高完成度样板的 KPI 卡常同时包含四元组：主数值、上期 / 去年同期参考、增减幅、方向符号或颜色编码；首版复刻时优先保留这四类信息，不追求装饰细节一步到位。

### 3.4 卡片式分析网格

代表样板：E-Commerce、Digital Ads、Golf、Merchandise、Sales Dashboard #VizOfTheDay。

视觉特征：主内容区由多个白色或浅色卡片组成，每张卡负责一个图表主题；常见组合为 KPI 卡、排名表、趋势图、地图、散点、donut、热力矩阵。

XML 启示：

- 先用固定 dashboard size 和 `layout-flow` 做二维网格。
- 每个卡片作为独立容器，内部挂 1 到 3 个 worksheet zone。
- Tableau 原生不稳定支持真正 CSS 圆角 / 阴影；首版用浅背景、边框和留白近似，高阶视觉再考虑 `bitmap` 背景。
- `Overview + Detail + Records` 的多页拆分，比单页无限堆卡片更接近高完成度样板的阅读方式；如果主题较复杂，应优先拆页而不是继续压缩单页密度。

### 3.5 漏斗 / Sankey / 转化流程

代表样板：Marketing Funnel、Email Marketing、Digital Ads。

视觉特征：用大面积流程图表达用户转化、邮件路径或投放漏斗，通常配合右侧 KPI 对比卡。

XML 启示：

- 这类页面依赖复杂 worksheet，而不是 dashboard zone 本身；dashboard 只负责容器和周边 KPI。
- Sankey / Funnel 可作为增强阶段，基础页先用条形漏斗或阶梯 GanttBar 表达，等用户确认后再引入复杂 polygon / path。

### 3.6 四状态对比编码

代表样板：Golf Superstore Performance Overview。

视觉特征：同一组小图里同时表达 Current、Selected、Previous、Below Previous 四种状态，通过深浅绿、灰线和红点做区分。

XML 启示：

- 这种表达非常适合 HEFANG 的“当前值 / 重点值 / 去年同期 / 未达预警”场景，但它是可选增强，不是所有页面都必须套用。
- 首版若要落地，优先把状态拆到多个 measure 或参考线，而不是在一个 mark 上叠太多视觉语义。

### 3.7 主色板复用策略

代表样板：Sales Dashboard #VizOfTheDay、Email Marketing、Marketing Campaign、Golf、Merchandise。

视觉特征：成熟样板的颜色不是随卡片零散选色，而是“一个主色 + 一个强调色 + 中性背景”的系统化配色。

XML 启示：

- 编译前先根据所选母版读取 PNG 主色，不要临时给每张卡片单独换色。
- 如果 HEFANG 品牌色尚未冻结，先沿用样板主色作为临时视觉稿；未确认前不要把任何候选品牌色写成项目事实。

### 3.8 暗色专题页

代表样板：Email Marketing、Marketing Funnel、Digital Ads 左侧说明区。

视觉特征：深蓝 / 黑底、高亮青色 / 粉色 / 紫色，用于强调专题分析和流程状态。

XML 启示：

- 暗色主题必须统一 worksheet 字体、轴线、网格线、tooltip 和 dashboard 背景，否则容易出现白底残留。
- HEFANG 经营看板首版建议以浅色为主；暗色只用于大屏或专题页，避免日常业务页阅读疲劳。

## 4. HEFANG 后续编译默认选择

| 使用场景 | 推荐母版 | 推荐原因 | 首版实现方式 |
|---|---|---|---|
| 销售 / 门店日报首页 | Sales Analysis + Sales Dashboard #VizOfTheDay | 信息层级清晰，卡片数量可控 | 左侧筛选栏 + 顶部标题 + KPI area cards + 趋势 / 排名 |
| 经营驾驶舱 | Golf + Merchandise | 覆盖 KPI、地图、Top、明细表和评分卡 | 浅色背景 + 侧栏 + 3 到 4 个主分析面板 |
| 达播 / 广告专题 | Digital Ads + Marketing Campaign | 日期 pill、漏斗、渠道 / 活动排名成熟 | 顶部日期参数 + KPI 卡 + 漏斗 + ranking table |
| 会员 / 转化专题 | Marketing Funnel + Email Marketing | 漏斗、Sankey、阶段 KPI 表达强 | 先做条形漏斗，再增强 Sankey / path |
| 高级品牌视觉页 | Merchandise | 视觉高级但实现成本高 | 先用容器近似圆角阴影，避免首版 bitmap 依赖过重 |

## 5. 联合学习后的编译顺序

1. 先选择视觉母版：左侧导航、顶部 hero、卡片网格、漏斗专题或经营驾驶舱。
2. 按母版确定固定尺寸：1200 × 800、1300 × 900、1500 × 900、1600 × 1000 或 1731 × 1200。
3. 建立 dashboard 粗网格：sidebar、header、KPI strip、main grid、right rail。
4. 每个卡片先用 worksheet 占位，保证 dashboard 可打开。
5. 再补字段 caption、格式、颜色、标题和参数控件。
6. 最后补图片 / 图标 / 阴影 / toggle / 参数动作。

## 6. 视觉验收清单

| 检查项 | 要求 |
|---|---|
| 文件映射 | `.twb` 与 `.png` 同名匹配；缺图样板不写视觉结论 |
| 尺寸 | PNG 实际尺寸应与 dashboard 固定尺寸基本一致；若恰好小 1px，默认视为 Tableau 截图边界的正常现象 |
| 布局 | sidebar、header、KPI strip、main grid、right rail 与目标母版一致 |
| 层级 | 先看到标题和 KPI，再看到趋势 / 排名 / 明细 |
| 色彩 | 一个主色 + 一个强调色 + 中性背景，避免每个卡片单独换色 |
| 元信息 | 页面应保留标题、数据日期 / `report_date`、`data_version`、Last Refresh 或来源说明 |
| 资源 | 使用 `bitmap` / shape 前确认资源可随 `.twbx` 打包，不把本机图片路径写成事实 |
| 交互 | 首版先静态可打开，再逐步添加 filter action、parameter action、toggle |
| Tableau 实测 | 只有用户打开确认后，才能说“渲染通过” |
