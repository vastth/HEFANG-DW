# 数云对接确认清单

| 问题编号 | 主题 | 需数云方确认的问题 | 数云方建议 |
|---|---|---|---|
| 1 | 加密参数 | AES 参数：AES-128 / ECB；密钥编码：hex（32 hex=16 bytes）是否正确？ | 数云提供java demo给到品牌方。 |
| 2 | 密文包裹格式 | ~{cipher}~{version}~ 是否对所有加密字段都适用？还是仅部分字段？version 可能有哪些值？ | 数云提供java demo给到品牌方。 |
| 3 | 推送频率 | 各表推送频率：实时/准实时/定时批量？（请给出大致周期，如 5min/30min/1h/每天） | 每小时同步一次 |
| 4 | 增量依据 | 增量判定字段是否统一以 update_time 为准？是否存在例外表/特殊口径？ | 增量数据根据update_time时间判断，然后根据相关表的主键进行更新 |
| 5 | 全量重推/重复推送 | 是否可能发生全量重推或重复推送？触发条件是什么？如何识别（批次号/特征字段/日志）？ | 一般不会全量重推，只有数据更新或者修复某些字段取值逻辑时，才有可能全量更新。没有标识可以参考。正常都是增量的更新推送。 |
| 6 | MySQL 版本要求 | 推送端支持的 MySQL 版本要求（5.7 / 8.0+）？是否限制存储引擎/参数？ | 建议版本mysql8.0及以上如遇到其他版本mysql，暂时无法判断影响。 |
| 7 | charset/collation 校验 | 推送程序是否会校验 ODS 表的 charset/collation/索引结构？我方 ODS 使用 utf8mb4_bin 是否可接受？ | 品牌方使用 utf8mb4_bin 格式 数云可以支持 |
| 8 | 连接数/并发 | 推送程序对数据库连接数：单店/全店并发连接大概多少？是否会开多连接并行写入？ | 品牌方按 20~50 并发预估配置也可以 |
| 9 | 京东 pin→xid 表结构与口径 | fdi_jos_pin_xid 中 xid 是否在 fdi_response JSON 中？字段名是否固定为 "xid"？ | xid是无法解密的，就是京东平台，对应会员的会员识别号。直接取过去用行。 |
| 10 | 京东 pin→xid 时效 SLA | fdi_jos_pin_xid 推送延迟 SLA：通常/最大延迟多久？是否可能缺失？ | pin，xid 关联关系依赖平台推送相关信息给到数云，数云侧延迟是半小时。但是平台侧延迟无法预估，以平台实际推送给到数云的时间为准。 |
| 11 | 京东业务表 plat_account 口径 | trade/order/refund 等业务表的 plat_account 是否已是 xid 口径（用于匹配）？是否需要再做 pin→xid？ | 订单中透出的身份字段是platAccount 对应京东的pinid，因此无论是正单还是退款单，平台账号都是pinid，如果要和会员关联，需要品牌方自己通过pin xid 做mapping后再使用 |
| 12 | 淘系跨表匹配口径 | TAO/TMALL/ALIBABA 等淘系平台：会员侧是否统一用 uni_id 作为跨表匹配键？业务表的 plat_account 是否与 uni_id 对齐？ | 淘系的业务，使用数云uni_id 作为跨表匹配键。 |
